# 统一字段重复方式实施计划

> **For agentic workers:** Use superpowers:executing-plans inline; preserve the existing uncommitted changes.

**Goal:** 固定次数和次数表达式合并为“按次数”；所有具有可靠单项边界和所属段边界的字段支持“重复至段末”，不适用时说明具体原因。

**Architecture:** 沿用 count 与 until:'end' 的配置格式、稳定字段 ID 和引用；普通字段的 byteLength 仍是每项宽度，旧 repeat/TLV 仍是整体区域宽度。流式扫描、完整解码、编码、LEN、映射及发送采用相同的重复语义。编辑器通过候选配置的编译诊断提示不适用原因，不修改原草稿。

**Tech Stack:** 经典 JavaScript、现有安全表达式编译器及 Node 测试，无新增依赖。

**Spec:** 本聊天用户在 2026-10-24 确认的“按次数／重复至段末”方案。

## Global Constraints

- 不改变旧协议 ID、字段引用、旧 count 数字或表达式、旧 repeat/TLV 的字节范围。
- 不猜测接收块边界；不允许零进度或消耗后续字段。
- 带同步／结束角色、自动序号、不能实例化的自动回填等约束必须提示冲突原因。

## Review Focus

- 整数字节不足一项时不能吞掉下一帧；空区域输出空数组。
- 变长字段没有单项边界、零长度或分支不推进时必须停止并报告原因。
- 嵌套直到段末只能使用当前项的可靠结束位置，不使用祖先的整个重复区域。
- LEN 对重复区域和每项一致；静态帧长不得使用一个元素的宽度。
- 自动序号、固定同步字段及回填规则不能误绑定为数组；旧字段引用保持。
