# 全局通道运算实施计划

**目标：**在统一的通道面板编辑全局运算与常量，每个控件独立选择可见通道，共享名称、颜色与计算结果。

**实施方式：**在当前工作区逐项实施，保留现有未提交改动，不进行 Git 提交或推送。使用经典脚本、Node 内置测试，无构建步骤。

## 已确认的计算规则

- `CH01`、`CH01[0]` 为当前值，动态通道的负索引为过去的采样点；常量通道索引从零开始。
- 四则运算和括号组合；`diff(x)` 为一阶样本差，`int(x)` 为逐样本累加，允许嵌套。
- `filter(signal, kernel)` 为因果卷积，kernel 必须是常量通道，初始不足的历史补零；信号必须放在第一个参数。
- 差分首点及不存在的历史索引为空；无效积分输入输出为空并保留累加器。
- 非有限结果推进采样位置，不绘制；曲线在无效点断开，CSV 单元格为空。
- 修改定义时保留受影响通道和下游的历史计算结果，新定义仅用于后续点，避免历史波形消失；主动勾选重建时重新计算受影响的历史波形。用户已确认 2A。
- 开启时异步重算保留的数值窗口，展示进度并追赶期间到达的数值帧。取消任务不能回写。

## 模块及接口

1. `channelOperations.js`：词法/语法解析、类型检查、依赖检查和增量求值。禁止执行任意 JavaScript；错误携带通道和输入位置。常量使用连续的 `[0]=...,[1]=...` 数组形式。裸数组只作为卷积参数，标量表达式用明确索引。差分方程系统作为可复用定义，通过 `filter(CH01,CH02)` 生成输出，用户已确认 1A。方程如 `y[n]=x[n]+0.5*y[n-1]`，初始状态如 `y[-1]=0`；x 为输入，y 为输出，输入和输出的历史初值均须明确，拒绝未来索引和瞬时反馈。
2. `computedFrames.js`：原数值 FrameBuffer 的共享读取视图，额外存储派生数值，原始字节只保存一次。对视图保留 `getValue`、`channelSlice`、时间及字节定位接口。
3. `channelConfigView.js`：统一波形和数值字节流通道行，名称/颜色共享，可见性独立；支持新增运算/常量、修改和删除，以及通道下方错误反馈。常量作为参数显示，不作为时域/FFT 序列。
4. 采集服务负责一次追加和一次计算；配置、绘图、搜索及导出读取同一套结果。原始格式导出仍为原始 RX/TX 字节。

## 重点风险

- 原始通道数变化不能让旧公式静默引用另一通道；通道引用使用稳定编号，编号冲突报错。
- 嵌套状态函数每个表达式节点仅计算一次/采样点。
- 长时间积分、NaN、除零与卷积溢出均不得中断采集。
- 无效输入保留编辑内容及错误提示，继续使用最后有效定义。
- 旧配置的非默认线性变换保留兼容读取；新配置界面不再提供线性变换项。
