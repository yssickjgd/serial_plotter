# 一键指令与多层编组实施计划

> 执行方式：使用 executing-plans，在当前会话逐项实现并验证。用户已确认功能范围；保留工程现有未提交改动，不进行 Git 提交。

**目标：**全局发送增加“常规发送／一键发送”，支持多层指令组及顺序批量发送。

**架构：**经典脚本、零构建。独立指令模型负责校验及树操作，执行器按快照顺序发送，独立视图负责树与编辑表单；复用 SendController 的传输和 TX 回调。

## 已确认范围与默认值

- 指令组按列表顺序递归执行全部子指令，组与指令都可一键发送。
- 指令配置名称、Hex／文本内容、总发送次数和间隔；暂不增加占位符及校验。
- 默认总次数 1、间隔 0 s；组内按上条指令的间隔等待后再发送下一条，最后一条无需额外等待。
- 指令树可创建、删除、折叠、修改所属组及上下排序；停止、断开、导入配置、销毁页面时取消剩余任务。
- 同时仅运行一种发送任务；开始常规发送会停止一键序列，反之亦然。正在提交的底层写入不能撤回，新的写入排在它完成之后。
- 保存到现有 version 2 的 send 字段；旧配置无指令树时使用空树。导入失败不改变当前状态。
- 发送前校验整个待执行子树，任何空内容或非法 Hex 均在发送前提示，避免半组执行；编辑中的草稿可保存。

## 验证重点

- 多层执行顺序、重复次数、等待与停止，断开后不能跨连接继续发送。
- 不允许循环归组、重复 ID、超深或超量导入，长名称安全显示。
- 常规与批量共享发送时，写入串行且 TX 仅记录一次。
- 标签切换不丢输入；长指令树内部滚动，不挤出工作区；发送区拖动保持可用。
- 配置往返、旧配置迁移、页面销毁和迟到异步回调。
