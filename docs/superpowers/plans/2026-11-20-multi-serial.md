# 多串口采集、同图显示与同步运算开发方案

**目标**　让同一工作区同时接收多个串口，支持跨串口时域同图、同步采样表和跨串口公式。各串口可使用不同波特率、帧结构、采样率与时间来源。

**架构**　以持久化的数据来源 ID 管理连接、采集与通道。各来源保留独立原始记录和样点，波形通过统一时间轴叠画，同步采样表按配置将不同来源映射到共同采样时刻，再执行跨源公式。

**运行方式**　沿用经典脚本、Chrome／Edge Web Serial、直接打开 `index.html`、现有 GPU 绘图与后台任务池。引擎配置继续支持保存、导出、导入和旧配置迁移。

## 时间模型

每条记录保留来源 ID、采集会话 ID、来源内帧序号和原始字节区间。接收记录保留电脑时钟和相对于同一采集时间原点的单调时刻。提供设备时间时，额外保存原始时间字段和换算后的采样时刻。改变显示时基不会改写采集原始记录或帧解析超时。

| 时间来源 | 计算规则 | 可用于 |
| --- | --- | --- |
| 电脑接收时间 | 在串口读取回调处记录。一个读取块可能包含多帧，同一个接收时间下按来源和帧内顺序稳定排列。 | 收发排查、粗略同图。 |
| 固定采样率 | 用户配置采样率，JustFloat 的 1 kHz 对应 1 ms。设定会话起点后，按设备帧序号和采样周期计算。配置了设备帧序号时，跳号保留时间缺口。只有应用接收帧序号时标为估算，整帧丢失无法凭帧数恢复。 | 高频周期信号的时域展示。共用序号、时钟及起点得到确认后可用于跨源对齐。 |
| 设备时间戳 | 每路可选择字段或通道、时间单位和计数回绕方式。共用设备时钟时直接使用。独立时钟通过共同事件校准偏移，多对事件可估计漂移。 | 跨设备精确比较和同步运算。 |

固定采样率的每路首帧可用其电脑接收时刻作为粗略落点。共同触发或已知共同起点可提供跨源锚点。同为 1 kHz 的两路各自从序号零开始时，界面仍标记为估算。多个设备的第 N 帧只有在共同采样序号定义成立时才代表相同采样时刻。

设备重启、断开、重连和时间倒退划分新的连续段。解析规则切换只影响所选来源，保留已有历史的规则与时基信息。配置持久化时基规则，运行时锚点按采集会话管理。对较大的整数时间戳先用整数相减，再转换为相对时间用于绘图，避免丢失低位精度。相位测量、逐点运算和导出显示所选时基及对齐质量。

共同设备时钟的典型来源是同一控制器上的硬件计时器，两个串口发送同一次采样的计数。两个独立控制器可以在共同脉冲边沿锁存各自的本地计数，并发送同步事件 ID。一次匹配事件提供偏移标定，多次匹配事件用于估计漂移；实际精度取决于脉冲捕获以及采样时间戳的精度。

跨串口公式默认允许近似对齐。来源使用电脑接收时间或固定采样率估算时，同图、同步表和公式结果均标注「近似对齐」。每路可相对所选参考来源手动设置有正负号的整数毫秒偏移，初始值为 0，支持直接输入和 1 ms 步进。界面明确标注正值向后移、负值向前移。偏移应用于跨源同图和该同步表的匹配，原始记录保留实际时间与偏移设置。调整偏移后可重新计算相关同步表与公式结果。手动偏移可纠正固定时间差，长期漂移仍由设备时钟校准处理。

固定采样率的丢帧识别依据按可靠性处理。设备帧序号跳号时保留缺失样点对应的时间缺口，后续仍按设备序号对齐；设备时间戳按实际跳变量映射。只有接收时间和应用计数时，USB／浏览器合批与真实丢帧无法可靠区分，接收间隔只能提示疑似断续，不用于自动插帧或改变历史相位。串口确认中断、重连或设备重启时，从新连续段重新建立时间锚点。

同速异起点支持手动校准。例如要把读数 1000 s 的来源移动到读数 1 s 的参考时间，在该来源输入 −999000 ms。首先以统一时基换算原读数，再施加用户偏移。偏移在全图、搜索定位、同步采样与同步导出上保持一致。

## 用户操作

- **通讯**支持新增串口来源、命名、独立连接与断开。每路显示波特率、RX／TX、解析错误和历史占用。每个打开的串口沿用 64 KiB Web Serial 缓冲。浏览器负责端口授权，应用保存来源 ID 和配置；同型号口无法唯一辨别时由用户确认。断开一路后历史可查看，其余来源继续采集。
- **数据引擎**增加来源选择。每路独立配置原生数据、数值数组或自定义帧、通道映射、空闲间隔及时间来源。协议模板可供多路引用，每路单独持有解析状态。跨源同步采样表与公式在数据引擎内统一管理。
- **波形控件**支持按来源勾选多个通道。时域共用时间轴，各路保持原采样率，光标显示实际样点时刻或插值状态。不同来源仍分别进行 FFT，并使用各自采样率投到共同的 Hz 轴。测量跨源相位或时延时使用同一同步采样表和分析窗口。
- **位姿控件**支持选择来源，默认从同一来源的同一帧读取一组姿态参数。混合来源的姿态输入可绑定同步表中同一个输出时刻的值，任一必需值缺失时该时刻显示为无效。
- **字节流控件**支持选择单路来源，另提供按接收时间合看、标明来源的记录视图。Hex、文本和协议检视分别使用每路规则，字节偏移始终属于原来源。发送区明确显示目标连接。常规循环和一键发送任务启动时锁定目标会话，断开后结束该路发送任务。
- **定位与搜索**保留来源、会话、时间和原始字节位置。跨源定位通过统一时间轴映射，超出对应来源的历史范围时显示缺失。字节位置始终和来源、会话组合使用。
- **左侧「导出数据」**保存所选来源的原始 BIN 或 Hex，包含未成功解析的字节。原始 BIN 延用现有默认值，Hex 默认 RX＋TX。无活动控件时也可导出。
- **右侧「控件属性 → 导出数据」**提供成功原帧 BIN／Hex、普通 TXT、数据引擎 TXT、数据引擎 CSV。普通 TXT 仅对显示「文本」的字节流开放，沿用所选来源的字符集和记录边界。数据引擎 TXT／CSV 跟随波形的可见通道、位姿的绑定通道或引擎字节流的所选通道／字段。导出区不编辑采集规则或另配通道。弱规则警告但成功解析的帧仍可导出。
- **跨来源导出**的 BIN 按来源输出独立文件，保留各自线序和同一来源内接收次序。Hex 同样按来源导出，可使用既有时间戳和方向标记。同步表 BIN／Hex 回查参与该控件所用通道的成功原帧，以来源、会话和帧标识去重，避免不同串口相同字节偏移发生碰撞。同步 CSV 可附输出时间、采样状态及来源时间或字节位置。无可用数据时禁用相应导出，并提示需要的控件或设置。

## 同步采样表与跨串口公式

1. 同步表选择参考时间轴、参与通道、输出频率、允许的时间偏差及有效期。每个输出样点保留各输入的源时间、样点序号、字节位置和状态。
2. 支持按字段选择取最近值、保持最近值或短间隔线性插值。实时默认保持最近的有效值；最近值和线性插值若需要未来样点，应等待到明确的输出期限，并显示由此产生的延迟。超出容差或连续段边界时输出空。源采样和统计规则保留原始数据；只对同步输出做重采样。
3. 公式支持来源限定名，例如 `chassis.CH00023 - gimbal.CH00005`。来源键与界面别名可分别管理，公式应用时按稳定来源 ID 和通道 ID 绑定。已有来源内的 `CH00023` 或通道名称沿用。不同来源重名时要求明确限定名，来源改名、通道排序后绑定继续指向原对象。
4. 复用运算通道、历史索引、状态函数和校验。跨源表达式在同步表计算，状态按输出与连续段隔离。缺样传播为空，时域图留下断口。原始值、保持值和插值值在选择、导出与悬停中可区分。验证拒绝循环依赖与无效引用。
5. 历史重建复用实时的校准、采样和公式逻辑。重建时保留每个来源的快照边界，并验证过渡到实时后同步点没有漏算或重复。来源规则变更只使相关同步表和公式重算。

## 落地顺序与验收

| 工作项 | 代码范围 | 验收 |
| --- | --- | --- |
| 1. 来源注册与配置迁移 | `app.js`、`serialEngine.js`、`widgetConfig.js`、`configStore.js`、`workspaceStorage.js`。注册来源、连接会话、保存绑定，旧配置迁为单来源。 | 两个串口可并行连接、各用不同参数。重连后保留正确的来源绑定。重复选择同一个实际口有提示。同型号设备有人工确认入口。 |
| 2. 隔离采集与解析 | `captureService.js`、`captureHistory.js`、`captureMemory.js`、`dataEngine.js`、`dataEngineView.js`。共享后台任务池和全局历史内存预算，按来源维护帧、字节偏移、TX 和统计。 | 一路残帧、超时、拔插、重建或高流量时，另一路帧边界与计数正确。验证内存回收、每路公平性和历史来源标识。 |
| 3. 时基与多源控件 | 在独立时间轴模块内处理时间单位、校准、回绕、分段和手动偏移。适配 `widgetController.js`、`plotter.js`、`monitorView.js`、`poseView.js`。 | 两个不同采样率的时域曲线共用时间轴。验证正负 1 ms 步进、保存恢复和参考来源标记。模拟串口合批时，设备或固定采样时间保持各自节奏。断开或超出历史范围的区段断开曲线，来源显示准确。 |
| 4. 同步表和公式 | 同步采样模块、`channelOperations.js`、`computedFrames.js`、`channelRegistry.js` 和补全界面。 | 用 1 kHz 与 200 Hz 的已知信号对比最近值、保持和插值。近似时基默认可运行并带状态标记，手动偏移后受到影响的结果正确更新。覆盖漂移、缺样、回绕、重连、来源重名、公式历史索引，并验证实时与重建一致。 |
| 5. 公共工具与压力验证 | `workspaceTools.js`、`engineExport.js`、`captureExport.js`、`sendController.js`、`commandRunner.js`。 | 验证跨源定位、左右导出入口、按来源分文件、同步原帧复合身份去重、同步表 CSV 和发送目标锁定。实机双串口连续三分钟，先建立分别接收的基线，再在支持的设备上验证 2 Mbaud、全屏 16 波形、每窗 60,000 点的组合压力。逐路记录帧数、时间戳跳变、解析错误、读取间隔和内存。 |

实机验收记录各设备使用的时间来源。设备提供共同事件时，补测时钟校准、时间单位和计数器回绕。其余设备用电脑接收时间或固定采样率验证近似对齐及手动偏移。集成阶段执行 `npm test`、`npm run check`、`git diff --check` 和真实浏览器操作验证。
