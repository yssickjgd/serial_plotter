# 自定义协议流式解析优化

**目标：**减少拆包后的重复扫描、校验和解码的重复工作，以及粘包时的缓冲复制；保留协议配置、错误记录、时间戳和工作线程兼容性。

**实现方式：**沿用经典脚本及安全表达式预编译，不执行用户 JavaScript。布局扫描改为可挂起的状态机，字段长度、分支及已读取数值可复用；接收缓冲使用读写游标及按需扩容。完整解码结果仅在整帧验证后发布。

**执行：**使用 writing-plans、executing-plans、TDD；在当前包含既有未提交功能的工作区中实现，保留这些改动及 serial_config.json 的删除状态，不提交或推送。

- [x] 编写先失败的增量解析测试：中间结果不发布、已读字段不重复读取、长分隔段不反复搜索、元数据和字节覆盖不变。
- [x] 将布局扫描改为可暂停、恢复的执行状态；已知整帧边界直接等待完整候选，变长布局保存栈及当前字段。
- [x] 内部传递已知帧长与布局，校验复用位置，解码复用已读标量和分隔位置；公开 decode 仍完整校验输入。
- [x] 接收缓冲采用有界容量与游标；移除逐帧复制剩余数据及元数据数组 shift，消费／重置／格式切换时释放失效状态。

## 审查记录

- 整帧范围变量参与的兼容扫描必须重验候选切片，不能直接相信针对整个接收块得到的长度；已以粘连两帧的反例回归验证。
- 暂停扫描不保存每字段的完整历史上下文；仅保存校验实际引用的窄上下文，避免 1500 字段案例的二次内存增长。
- 窄上下文仍保留 CURRENT／PARENT 的延迟读取及 LEN 的实际编码长度语义，覆盖校验先于长度字段的配置。
- 结束特征前缀表按长度选择 8／16／32 位存储，覆盖超过 255 字节的重复特征。
- 性能及内存记录见 `docs/protocol-stream-performance.md`；三轮对照中逐字节拆包样例为原吞吐的约 2.5～3.0 倍。
- 最终验证：`npm test` 1252 项通过；`npm run check`、跟踪文件及本轮新增文件的差异检查通过。

## 风险与约束

- 已读取字段和临时布局不得跨帧、跨格式或跨接收间断复用。
- 输入块不是帧边界；分隔特征本身跨块时也必须正确匹配。
- 无效帧和噪声按真实字节位置报告一次；回调拿到的字节不受后续缓冲复用影响。
- 多段及互斥分支校验必须使用各自实际字段范围，不能误用同名字段。
- 整帧长度依赖整帧范围的特殊旧式表达式保留兼容处理，不以性能优化改变协议含义。
