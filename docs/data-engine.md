# 数据引擎使用说明

继续直接打开 `index.html` 使用，无需构建。左侧上半区是通讯、控件与导出，下半区是与控件选择无关的数据引擎；两区独立滚动，拖动中间分隔条调整比例。

通道管理页的列表随剩余高度伸缩，只在列表内滚动。空间允许时优先保留至少五行收起状态的通道；窗口过矮时临时压缩，不改写保存的上下比例。帧解析与通道管理共用同一高度约束，切换标签不移动分隔条。自定义通道的上移、下移按钮并排显示，收起行与原始通道保持相同行高。

## 配置与应用

“帧解析”中的参数是草稿。校验通过后点击“应用解析配置”，此前继续按旧规则采集。草稿和已应用配置分别保存，刷新不会把未应用参数当成正在运行的规则。

| 模式 | 数值输出 | 字节流选择“数据引擎”时 |
| --- | --- | --- |
| Raw_Data | 不产生采样值；常量及系统响应仍可查看 | 原始记录及说明 |
| Data_Array | 固定类型、固定帧长的数组 | 通道数值 |
| Self_Defined_Frame | 各消息独立序列和同步采样表 | 消息、状态和结构化字段 |

Data_Array 的类型、端序、通道数、帧首、帧尾和校验从旧配置迁移。每帧通道数表示线上数组长度；缩短它不删除已注册的通道或绑定，未收到的字段为空。扩展原始通道目录会顺移新增通道编号并更新引用，稳定身份保持不变。

“重建历史数据”开启时异步重新解释保留的原始字节；关闭时从当前位置记录受影响输出。原始 Hex／文本来源及 TX 不会因为数值解析改变而清空。全局清空会取消旧任务并清空全部来源。

## 通道管理

提交通道名称后，右侧已打开的波形／数值字节流通道列表及位姿绑定同步更新，保留当前筛选、滚动位置和勾选。运算通道、常量数组和差分方程系统的编辑区域按内容撑开，不预留固定空白；编辑框拉伸和错误提示换行后，列表位置也随实际高度更新。左右侧栏没有内容的说明和状态行不占空间。

- 原始、运算、常量数组及差分方程系统合计最多 65535 个。显示使用 `CH00001`～`CH65535`，输入可简写为 `CH1`、`CH01`。
- 名称可用中文、字母和下划线，后续可含数字；不允许空格、运算符、零宽字符、保留函数名及重复名称。
- 公式可使用 `温度 + CH00002`、`温度[-1]`、`DIFF(温度)`、`INT(CH1)` 和 `FILTER(...)`。应用后的引用按身份绑定，改名和排序不改变依赖对象。
- 输入时提供候选，方向键选择，Enter／Tab 插入，Esc 关闭。输入法组字时不抢占按键。
- 旧配置中的非法或重复名称继续显示，并在下方提示；修正前只能使用编号引用该通道。
- 左下编辑名称、颜色及定义；右侧波形／数值字节流通道列表同样支持名称和颜色编辑，立即全局同步，位姿继续配置通道绑定。各控件可见性独立。
- 右侧可按五位编号、简写编号或名称搜索，Enter 定位首个匹配；波形与数值字节流会话内共用搜索文字。搜索和分类筛选不改变已勾选通道，改名后匹配结果同步更新。原生颜色选择器连续预览期间不重建列表。
- 通道列表与搜索、导出、位姿选择采用有限窗口或分页，不生成 65535 行 DOM。容量上限不意味着所有通道均可同时高速绘图。

## 自定义协议

选择模板或新建协议后，打开“编辑与样例预览”。宽面板提供帧结构、消息字段、校验、JSON 和 Hex 预览。点击字段可查看其字节和位范围，点击字节可定位字段。复杂条件分派和复用结构也可编辑 JSON。

协议的消息标识、字段标识独立于显示名称。字段映射需明确选择已有原始通道或新建通道；新建映射在应用前仍是草稿。只投影选定标量字段，完整的字符串、原始字节、嵌套结构和数组仍保存在结构化记录中。数组索引不存在时为空。

### 最小变长协议示例

以下布局是 `AA + 长度(uint16) + 命令(uint8) + 载荷 + CRC16`，长度字段表示载荷字节数，所有偏移从零开始，结束位置不包含该字节：

```json
{
  "id": "sensor-v1",
  "name": "传感器示例",
  "endian": "little",
  "framing": {
    "header": [170],
    "length": { "offset": 1, "type": "uint16", "adjustment": 6 },
    "maxLength": 1048576
  },
  "command": { "offset": 3, "type": "uint8" },
  "payloadOffset": 4,
  "payloadEnd": -2,
  "checksums": [{
    "type": "crc", "width": 16, "polynomial": 4129,
    "init": 65535, "reflectIn": true, "reflectOut": true, "xorOut": 0,
    "start": 0, "end": -2, "offset": -2, "endian": "little"
  }],
  "messages": [{
    "id": "sensor.status", "name": "状态", "command": 1,
    "fields": [
      { "name": "clock", "type": "uint64" },
      { "name": "count", "type": "uint8" },
      { "name": "values", "type": "float32", "count": "count" }
    ]
  }]
}
```

数值表达式限于受控的运算、字段引用和允许函数，不执行 JavaScript。支持字段端序、偏移、位段、枚举、布尔、字符编码、结构复用、动态数组和多级分派。多个校验可分别配置覆盖范围及保存位置。

`uint64`／`int64` 保留精确整数；结构化显示、搜索与 CSV 使用十进制文本。超出安全整数范围时不会静默转换为浮点通道。帧长、数组数量、字段展开和后台任务都有边界，异常帧不会触发无限分配。

### RoboMaster 2027

内置模板依据用户提供的《RoboMaster 2027 机甲大师高校系列赛通信协议 V1.0.0（20261029）》第一章串口命令和 CRC 附录，采用官方仅计 payload 的 data_length。旧 `dvc_referee.h` 不自动导入；MQTT、Protobuf 和裁判系统专用图形绘制不在此次范围内。已保存的旧模板和自定义长度保持原样；升级需在编辑器显式载入最新模板、核对通道映射后应用。协议与未改变含义的字段 ID 保持稳定。

模板在有冲突的消息中保存说明：以详细字段表解码，额外字节作为未知尾部保留。发送有歧义的布局时，必须主动选择“详细字段布局”，未选择时阻止发送。协议中的频率、赛规及发送限制是说明信息，调试工具不会自动执行比赛权限或速率规则。

## 同步采样

自定义帧的每种消息及子消息拥有独立序列，其他消息不会增加其采样点。跨消息运算可使用“全局同步采样表”：默认 1000 Hz，首次有效消息后启动，按浏览器接收顺序因果保持最近值。

采样率及字段有效期集中在“帧解析 → 因果同步采样”，仅在自定义帧草稿中显示；与其它解析参数一起校验并显式应用。

- 首次收到前为空；之后可区分新值、保持值、缺失值和过期值。
- 每个映射通道可设置有效期，0 表示关闭。到期后为空，不补零。
- 暂停、断开时停止；恢复后从新消息开始，不补采中间空档。
- 保存事件和保持区间，读取、绘图或导出时按需生成采样，不逐点复制所有原始值。
- 运算定义全局共用，各采样输出的积分、差分与滤波状态隔离。
- 波形及位姿右侧可选消息序列或同步表。同步 FFT 使用指定采样率，而非设备实际消息刷新率。

## 查看、搜索、发送与导出

字节流的 Hex／文本查看始终读取原始字节；字符集及文本断帧在所有字节流控件间共享，不改变引擎的逻辑帧。数据引擎查看自定义消息时可选择字段路径，父结构路径包含其子字段。

暂停后，搜索来源默认当前激活控件。结构化记录可按字段路径搜索数值误差、文本或精确 64 位整数；Hex／文本仍支持跨帧搜索。同步保持值定位到它的来源消息，来源已淘汰时明确提示，不制造边界命中。保留既定的就近、首次反向上／下一个及循环搜索行为。

常规发送与一键指令均支持“协议消息”：选择协议、消息、填写字段，预览最终 Hex。长度和 CRC 自动计算；任务开始固定协议修订，每次成功写入后推进序号，失败不推进。普通指令、嵌套组、次数、间隔、停止和两类任务互斥继续使用原流程。

导出仍在左上“导出数据”：

- bin／hex／txt：明确选择基础原始记录或某解析来源，支持既有方向与文本元数据配置。
- 结构化消息 CSV：选择“结构化消息记录”，列按字段路径展开，数组及字节字段使用可还原 JSON 单元格，精确整数不转浮点。可用路径限制字段。
- 同步 CSV：按采样点导出，缺失值留空，可附新值／保持／过期状态及来源字节位置。
- 时间戳选项控制 CSV 时间列；大文件分块写入，结构化列发现也异步分片，记录被覆盖或来源变化时终止并说明。

## 保存、资源与验收

配置版本 3 保存全局引擎、各模式参数、协议库与草稿、通道身份、同步规则、控件设置及上下比例。完整内容异步保存到 IndexedDB，少量配置保留兼容镜像；旧存储仅在新事务提交成功后完成迁移。读取失败时停止自动覆盖，导入成功后可恢复保存。配置不包含采集历史。

每个来源仍受最大帧数及全局内存预算约束；默认 4096 MiB 是采集存储估算上限，不是浏览器进程硬上限。静态响应、画布、驱动及 JavaScript 运行时另有开销。

波形的全局采样点数可设为 2～65536。输入值超过“每个来源最大帧数”时，会同步提高容量并更新左侧输入框，保留当前数据；调小采样点数不会缩小缓冲区。系统响应时域的点数仍按控件独立保存，不扩大采集容量。设置会随配置保存，切换控件及重新加载后保持一致。

右侧波形及数值字节流的通道配置使用标签页自身的滚动区，列表不再另限十行高；大量通道仍使用虚拟化。左侧数据引擎的通道管理保持随剩余高度伸缩的独立列表。

协议库校验失败时，配置读取提示会包含协议名称／编号及可确定的字节范围。重叠的自动写入区域仍须修正，程序不会猜测修改帧规则；读取失败后停止自动保存，保留原存储内容，导入有效配置后恢复。

验证命令：

```text
npm test
npm run check
node scripts/benchmarkDataEngine.js --duration 60
```

性能脚本同时检查数组和混合协议各 23 通道、5000 帧／秒、60 秒，核对完整字节哈希、保留数值、同步来源和估计内存。它仅测量 Node 采集链路；浏览器绘图帧率和用户操作延迟需在实际 Chrome／Edge 页面验收。

### 2026-10-21 采集链路实测

数组和混合协议同时持续运行 60.025 秒，各解析 300000 帧，丢帧为 0；输入和解析字节哈希一致，最新 5000 帧的数值、原始字节及同步来源均核对通过。测试调度延迟的批次随后补发，不计作丢帧。

Node 事件循环延迟 P95 为 7.075 ms，最大 20.718 ms；两个引擎估算采集内存峰值分别为 28.69 MiB 和 68.29 MiB，整个测试进程 RSS 为 426.18 MiB。此结果不包含浏览器画布、显卡驱动或真实鼠标交互的耗时。当前工具未获准访问本地浏览器页面，因此本轮未完成 Chrome／Edge 的视觉和绘图帧率实测。

### 自定义编辑器与 TLV 更新后复测

同日更新后的 60.015 秒测试中，两路仍各完成 300000 帧、丢帧 0，原始字节哈希、保留数值及同步来源校验通过。事件循环延迟 P95 为 7.031 ms、最大 20.002 ms。测试范围仍仅限 Node 采集链路，不代表浏览器绘图或交互延迟。

协议编辑器的命名样例批量解析和字节流检查复用采集服务的后台任务池，继续保留两个逻辑核；没有可用后台线程时分片让出主线程。修改草稿后旧检查结果不会回写，关闭编辑器不销毁公共任务池。
