# 自定义协议流式解析性能记录

## 本轮修改

- 应用协议时预处理字段宽度、分隔前缀表和可提前检查的校验规则；表达式仍使用既有安全解析树。
- 内容决定长度的帧使用可挂起扫描，接收不足时保存字段及循环进度。已读取的标量、字段范围和分隔位置供校验及结果构造复用。
- 长结束特征增量匹配，前缀表根据长度使用 8／16／32 位存储，覆盖超过 255 字节的重复特征。
- 接收缓冲按需扩容并使用读写游标；消费一帧仅复制交付回调的字节，不复制整个剩余输入。元数据也使用游标，保留真实首字节时间及位置。
- 仅为校验表达式保存窄上下文；`CURRENT`／`PARENT` 路径延迟读取，`LEN` 复用实际编码长度，避免暂停扫描持有全部历史字段快照。
- 缓冲容量、接收元数据和暂停扫描状态接入全局内存预算。重置、清空、字节间断或格式切换后失效状态不会跨帧使用。

固定整帧长度或可提前求出的长度会等待完整候选后解码。依赖未知整帧范围的特殊表达式保留兼容扫描，并在候选切片上重新检查长度。完整解码结果仍在整帧验证后发布；不保证所有校验、错误重同步和复杂布局只读取每个字节一次。

## Node 对照测量

2026-10-22，同一机器、相同 Node VM 加载方式，旧／新解析器交替独立运行三轮，取耗时中位数。样例验证输出数量、有效状态、数组长度及末尾数值；正确性回归另外完整比较字段、字节位置及原始字节。

| 样例 | 旧耗时 | 新耗时 | 吞吐倍率 |
|---|---:|---:|---:|
| 23 通道、3000 帧，按一帧接收 | 264.04 ms | 196.69 ms | 1.34× |
| 23 通道、500 帧，逐字节接收 | 313.31 ms | 124.30 ms | 2.52× |
| 512 通道、40 帧，逐字节接收 | 537.63 ms | 177.68 ms | 3.03× |
| 23 通道、3000 帧，65536 字节粘连接收 | 292.78 ms | 167.87 ms | 1.74× |

这是独立的接收解析基准，不包含浏览器、绘图、通讯速率或完整采集服务，不能作为界面 FPS 或实际设备吞吐承诺。新解析器启用了开发工作计数，正式采集默认关闭。

运行当前版本：

```text
node scripts/benchmarkProtocolStream.js
```

对比另一份受信任的本地解析器快照（可选参数使用相同 VM 加载方式）：

```text
node scripts/benchmarkProtocolStream.js path/to/protocolEngine.js
```

## 暂停态内存及回归

对 1500 个独立数值字段、末尾缺少 2 字节的案例，以 `--expose-gc` 测量暂停态新增保留堆：早期优化实现保留所有字段上下文时约 51.6 MB，改为窄上下文后为 708400 字节；解析器预算估算为 674974 字节。测试使用宽裕的 16 MiB 门限防止二次增长回归，内存数值仍属于估算。

`tests/protocolStreamPerformance.test.js` 覆盖：逐字节拆包、多帧粘连、重叠及跨块分隔符、噪声／错误校验后的重同步、字节间断、重置／格式切换、回调字节所有权、内存预算、TLV／重复段／精确 64 位值、工作线程工厂、首字节时间、整帧范围兼容表达式，以及校验中的后续 `CURRENT` 字段和 `LEN`。
