# 自定义协议编辑器

从左侧“数据引擎 → 帧解析 → 自定义帧”的“当前协议”下拉框选择协议，点击“打开协议配置面板”。协议库为空时也可打开面板并新建或添加模板。字段映射独立显示在“字段 → 数值通道”配置组。草稿和当前采集规则相互独立；校验通过后点击“应用协议”，才会按照“重建历史数据”开关更新采集输出。

## 编辑流程

1. 左侧协议下拉框保持可见。“结构大纲”显示当前协议的整帧、字段、结构体和分支，可像文件夹一样展开／折叠；搜索临时展开匹配路径，清除搜索恢复原折叠状态。方向键导航，左右键展开／折叠，Enter 选中。
2. 右侧相邻的“协议与字段编辑”标签集中提供协议、字段、排序、撤销及重做操作；协议按钮依次为新建协议、删除协议、导入协议、导出协议、复制协议。“新建字段”在当前字段之后插入默认字段，“新建子字段”在选中结构体或分支内插入，数据类型在右侧修改。协议库允许为空；RoboMaster 模板通过“RoboMaster 模板”明确加入。已有同标识协议先打开原配置，可确认“载入最新模板”替换草稿，支持撤销，仍需“应用协议”才影响采集。

   “RoboMaster 模板”以较小字号固定在左侧编辑栏底部，不随操作按钮列表滚动。字段操作不再提供上移／下移按钮，仍支持画布拖动及 Alt＋上下键排序。“新建子字段”仅在选中可包含字段的结构体或已有分支时可用；普通数值、固定字节或整帧选中时不可用，悬浮可查看原因。分支为空时先添加分支；顶层添加使用“新建字段”。
3. 字段统一使用表达式变量名呈现，内部 ID 用于映射；改变名称和排列不会按位置重新绑定通道。旧显示标签仍保存在配置中以兼容导入。
4. 拖动手柄调整顺序或移入子段，也可使用箭头和键盘操作。整个子段及其内部字段一起移动；不能移入自身。画布分支标题和右侧分支标题均提供拖动手柄，可在同一个条件段内调整分支顺序；`Alt + ↑ / ↓` 也可调整，`Esc` 取消，撤销／重做保留字段和分支身份。不同条件段之间不能拖动混合分支。
5. 编辑器占满浏览器页面，先按左侧协议导航、中央编辑区、右侧属性划分三列；中央再上下分为结构编辑与字节／样例／问题区。右侧变量名常驻在属性标签上方，配置分为“基础设置／高级设置／关联信息”；引用跳转会打开对应标签。左右栏独立滚动，中央分隔条不改变侧栏高度。样例、折叠状态、标签及滚动位置单独保存，不改变线上协议结构。
6. 问题列表同时显示字段路径、规则名称及关联字段；点击可定位字段或规则属性。协议整体问题会明确标注，无法定位时保留原始节点 ID。

错误横幅、字段错误、问题列表及其悬浮提示、样例解码和批量检查、规则结果均使用中文说明。字段路径、表达式和编码名称保持原样；JSON 格式错误在浏览器提供位置时显示行列或字符位置。中文仅用于界面呈现，不改动协议、错误代码或定位信息。

结构画布只有一棵“整帧”字段树。同步固定字节、长度及校验值存储、命令分支都作为实际字段参与排列；附加验证在并列的“规则约束”标签中配置。点击整帧标题可配置整帧长度表达式、默认字节序和最大帧长；点击字段卡片编辑该字段。

点击卡片标题、说明或空白均可选中；点击子字段只选中子字段。互斥分支和 TLV 分支也可直接选中：点击分支标题、匹配条件或空白区域，右侧显示该分支的名称、匹配方式和对应条件。键盘聚焦分支后按 Enter／空格也可选中；左侧结构大纲同步选中。名称常驻属性面板顶部，“关联信息 → 打开所属字段”可返回父字段并编辑选择表达式及完整分支列表。分支匹配值沿用父字段的数值进制，排序和撤销保留分支及子字段身份；删除确认仅针对当前分支。

重绘后焦点跟随当前选中的分支、字段或整帧，不回到分支的父字段；恢复焦点不会自动滚动画布或属性区。排序后的分支输入框按分支 ID 恢复，不按原列表下标寻找；字段拖动手柄、文本光标和撤销／重做按钮的焦点同样保留。撤销使选中字段消失时，回到最近仍存在的父结构。整帧结构、结构大纲和位内容不分页，中央画布使用一层垂直滚动，字段卡片自动换行。字节数与重复信息同行显示，例如 `2 字节 · 重复 3 次`；长表达式省略显示，悬浮查看完整内容。

已保存、导入、复制或编辑过的协议／字段删除前均需居中确认，只有本次会话刚新建且从未编辑的默认项可直接删除；编辑后再撤销仍需确认。自动保存不改变这一判断。删除可撤销，字段依赖不会自动移除或改绑，存在失效引用时需修正后才能应用。协议的外部引用保护保持有效。

## 流式接收

### RoboMaster 2027 V1.0.0 默认示例

默认示例依据 2027 V1.0.0（20261029）第 1 章串口协议（3–45 页）和 CRC 附录（75–78 页）。`header.data_length = LEN(payload)`，不包含命令码及末尾 CRC16；整帧长度为 `header.data_length + 9`，空 payload 时该长度字段为 0。发送时自动回填长度，再计算 CRC8 和 CRC16。此模板不解析第 2 章 MQTT／Protobuf 消息。

数据类型列表优先显示“位段”。默认模板的 20 个打包字段（比赛状态、双场地事件、RFID、哨兵与雷达信息、图形配置等）使用显式位段类型，按协议保留 1／2／4／8 字节宽度、子位偏移、枚举及保留位。未改变含义的字段 ID 保持稳定；改为保留位的位置不继续展示旧业务含义。普通整数及枚举仍使用原类型。已有协议不自动改写，需载入最新模板后应用并核对映射。

已保存、编辑或导入的协议继续使用自己的布局与长度规则，不会被自动覆盖。以前保存的 `LEN(payload) + LEN(checksum_0)` 自定义定义仍受支持。需要升级时，在“协议与字段编辑”点击“RoboMaster 模板”，确认“载入最新模板”，检查字段映射后点击“应用协议”；替换草稿可撤销。协议及未改变含义的字段继续使用稳定 ID，旧命名空间中的 `v1` 是历史身份，不表示当前文档版本。

新版血量为 24 字节，场地事件为两组 uint32（8 字节）；伤害数据为 7 字节并包含命中序号、int16 命中坐标。RFID 为 6 字节，雷达状态为 8 字节，雷达自主决策子命令 0x0121 为 13 字节并含装甲加固请求及圆心；无线场地状态 0x0A04 为 12 字节，无线增益状态 0x0A05 为 47 字节，0x0311 为 60 字节。移除新版未列出的 0x0302／0x0306／0x0309，接收时按未知命令保留原始内容。旧版三处长度冲突已在新版统一，发送不再要求选择详细布局。协议与字段 ID 中保留的 2026 字样是稳定身份，不代表模板文档年份。

默认模板使用“整帧结构＋规则约束”：

- 整帧长度表达式为 `0`（按内部字段确定），payload 和嵌套分支采用内部结构，不绑定 `data_length`。
- `header.data_length` 的“本字段的值表达式”为 `LEN(payload)`，用途为“解析定界＋验证”。已知固定命令直接按结构解析；机器人交互 `0x0200–0x02FF`、未知根命令及未知子命令显式使用该关系式取得备用边界。
- “数据段长度验证”默认完整帧验证、弱规则、自动回填。结构明确但长度值错误时仍输出数值并标记警告；未知段无法获得合法边界时重新同步。未配置的扩展字节不能延长已知命令结构，需要在模板中明确添加字段。
- “帧头 CRC8”：两个阶段、强规则、自动回填。接收不完整帧时可及时排除错误帧头。
- “整帧 CRC16”：完整帧验证、强规则、自动回填。完整帧校验失败保留错误记录，不输出数值，从可靠帧末尾继续。

CRC8 与 CRC16 的存储字段仍位于原来的位置，字段 ID 和范围引用保留；字段类型分别为 uint8、uint16，算法和覆盖范围在规则页编辑。所有示例工厂接口默认返回该新版模板；`legacySchema` 仅供显式使用旧表示进行兼容处理。

接收块不等于协议帧：一帧可以分多次到达，多帧也可以一起到达。未完成的字节及解析进度会保留；完整帧按规则强弱决定是否输出数值，同时保留诊断记录。边界尚不可靠的解析错误按协议的同步特征尝试重新同步。

协议应用时预处理类型宽度、表达式及校验规则；内容决定边界的帧使用可暂停的字段扫描，避免半帧到达后反复读取已完成的字段。长结束特征按增量前缀匹配处理，支持特征跨块及重复前缀；校验复用字段位置，解码复用已经读取的数值和分隔位置。

整帧边界已知时等待完整候选；依赖尚未确定的 `FRAME_LENGTH`／`REMAINING` 等变量的特殊规则保留兼容扫描，并重新验证实际候选帧，避免误吞下一帧。该优化不承诺所有协议的每个字节只访问一次：校验范围、复杂依赖和错误重同步仍可能重复访问。

接收缓冲采用有界容量及读写游标，避免多帧粘连时逐帧复制剩余内容。预留缓冲、接收元数据及暂停扫描状态计入内存预算；完成、清空或切换规则后丢弃对应临时解析状态。仍支持直接打开 `index.html` 和现有工作线程，不生成或执行用户 JavaScript。

开发时可运行 `node scripts/benchmarkProtocolStream.js` 检查完整帧、逐字节拆分及多帧粘连的 Node 解析吞吐；此结果不代表浏览器绘图帧率。构造 `StreamParser` 时传入 `{ trackWork: true }` 可读取 `work` 中的字段访问、实际标量读取、分隔搜索字节和缓冲复制字节计数，默认关闭以减少运行开销。

## 字节数与用途

字段先配置 **数据类型**，再配置字节数、变量名和端序。“重复次数”位于基础设置，适用于普通字段与结构体；偏移、启用条件及共享结构引用保留在高级设置。数据类型始终显示全部支持的选项，不按当前字节数过滤；主要用途通过互斥的 **内容约束** 下拉框配置。长度与校验表单直接展开在该字段的内容约束中，与全局“规则约束”编辑同一条规则。

| 配置 | 含义 | 示例 |
|---|---|---|
| 数据类型 | 按什么规则读取字节 | 无符号／有符号整数、浮点数、布尔、文本、原始字节、位段、结构体、互斥分支、TLV |
| 无约束 | 普通接收值 | 不添加字段主约束，仍可被其它字段引用或被校验覆盖 |
| 固定内容 | 本字段必须符合固定值 | 固定字节或数值；独立固定字节可承担帧头／帧尾 |
| 长度关联 | 本字段值与数据段字节数的关系 | 值表达式、仅验证／备用定界、检查阶段、强弱、发送回填 |
| 校验值 | 本字段保存检查结果 | 算法、字段范围或偏移表达式、检查阶段、强弱、发送回填 |

整数、浮点数和布尔值的字节数由类型确定：整数和浮点数按位宽使用 1／2／4／8 字节，布尔值使用 1 字节。选择类型后自动填写字节数并置灰；文本、原始字节、保留字节、位段、结构体、分支和 TLV 保留长度配置。普通字段和结构体的字节数表示每项宽度，切换类型保留重复次数；TLV 的字节数表示整个容器的范围。

打开已有协议不会自动改写其字段。旧配置的标量宽度不匹配时，界面显示类型所需宽度并提示原值，需点击“按类型修正字节数”明确修正。切换类型与既有固定内容、枚举、子字段、边界或长度关联冲突时，保留原配置并提示处理；不静默删除字段、规则或引用。

原始字节可作为接收值或固定内容，保留字节在数据类型中选择；整数可保留数值解码并验证固定内容。1／2／4 字节的独立无符号整数字段可选择长度关联或校验值。切换已有约束时先说明影响，再确认；对应旧规则停用并保留 ID，其它字段引用保持，支持撤销。存在多种旧主约束时显示“旧版组合约束”，不会在打开时自动简化。

旧协议的 `role: length`、`lengthSource`、长度表达式和 `type: checksum` 继续兼容；仅查看新界面不会改写它们。长度关联与校验范围始终引用稳定字段 ID；重命名、移动和撤销不会按位置重新绑定。切换为无约束后保留旧校验参数，重新选择校验值可恢复。旧版字段内校验保持原执行语义，可在全局规则约束中显式转换后配置阶段、强弱和回填。

旧组合明确选择保留长度关联时，会保留原长度绑定；重新选择校验值时优先恢复此前启用的那条规则，不会因为列表中另有一条较早的停用规则而改变校验结果。枚举字段切换内容约束时保留原数据类型及标签。

校验范围的起点、终点各自选择字段及“包含该字段”：起点包含从字段开头算起，不包含则从字段结束算起；终点包含算到字段结束，不包含在字段开头停止。底层仍保存字段 ID 与 `edge`，旧范围无需迁移。选择字节偏移／表达式时使用原半开区间语义。范围不能包含校验值自身。

数据段自身的长度放在“读取边界”中；“关联信息”只读展示备用长度来源、被哪些校验覆盖和其它长度引用，并提供定位入口。

结构卡片分别展示基础数据类型与实际用途，例如“长度 → payload”“校验 · SUM8”“固定 · 0xAA”或“保留字节”。点击用途提示可选中字段并定位到对应配置组，提示本身不保存第二份规则。

承担帧头或帧尾的独立固定字段使用原始字节类型；需先明确取消断帧角色，才能改成其它数据类型，避免编辑时静默改变断帧规则。

- 字段的正整数字节数表示固定宽度。
- **字段字节数为 0 表示变长**，必须指定数值长度字段、受限长度表达式，或引用相邻的独立固定字节字段。子段、分支和定次重复还可显式选择按内部字段确定长度；读取剩余字节的内容必须处在已有可靠终点的范围内。
- 旧长度绑定保留单位和字节修正，界面只读展示；新增长度关联使用值表达式。普通字段自身的长度表达式限定该字段，整帧长度表达式限定整帧。
- 整帧统一使用“整帧长度表达式”，单位为字节。输入 `32` 或 `16 + 8` 等常量表达式表示固定长度；**输入 `0` 表示变长，留空非法**。变长仍需内部字段具有可靠的长度或边界规则。旧的整帧字节数及长度来源选项不再单独显示，旧的自动长度配置呈现为 `0`。
- 动态表达式例如 `data_length + 9`、`header.count * header.width + 4` 或 `LEN(payload) + 9`。结果是包含所有字段的整帧总字节数；数值输入只引用位置确定的前置字段，`LEN` 引用可独立确定长度的数据段，不可循环引用 `FRAME_LENGTH`、`PAYLOAD_LENGTH`、`REMAINING` 等整帧边界变量。除字面值 `0` 的变长约定外，非法、自引用、非整数、非正数或超出最大帧长时拒绝应用或解析。
- 表达式输入支持字段路径、协议函数和内置变量补全，区分大小写；`LEN(` 内提示可引用的字段／数据段。使用 `↑ / ↓` 选择、`Enter / Tab` 插入、`Esc` 关闭、`Ctrl + 空格` 主动提示，`Ctrl + Enter` 仍应用协议。输入函数会补齐括号并将光标放入括号内；数字输入和中文输入法候选确认不会误插入提示。
- 单个无符号 8／16／32 位字段乘正整数、再加整数修正量的表达式，发送时仍按实际总长度自动回填。若该字段还控制数量、条件或偏移，或使用其它复杂表达式，则需在发送时填写相关字段值；最终编码长度必须与表达式一致。旧的整帧长度绑定显示为等价表达式，未编辑时保留原绑定；字段改名会同步更新可明确解析的表达式引用。
- 长度、校验范围和固定边界引用保存字段 ID；改名不会改绑。删除仍被引用的字段后必须修正引用才能应用。

例如 `AA 55 | 变长文本 | 0D 0A` 使用三个字段：前后是独立固定字节，中间文本的字节数为 0，长度来源为起止固定字节。文本不包含前后特征；特征跨接收块时等待完整数据。内容本身可能出现相同特征时，应改用长度字段或协议转义，不能靠猜测区分。

同一个数值字段可以同时用于展示、长度和条件判断。例如 `payload_length` 仍保留数值，后面的载荷引用它；`cmd_id` 仍保留数值，后面的条件分支引用它选择子段。无需为每个命令创建不同协议。

### 名称、数量与启用条件

- **表达式变量名**：长度、数量和条件中使用的名字，例如 `data_length`。以字母或下划线开头，后续可含数字。改名会更新能够明确解析的引用；稳定 ID 不变。
- **重复次数**：直接输入 `-1` 表示重复至所属段末，`0` 表示不读取、得到空数组，正整数或已读取字段的表达式表示读取次数。例如 2 字节无符号整数、次数 `3`，共读取 6 字节；也可填 `item_count`。表达式结果必须是非负整数，即使计算结果为 -1 也会报错，不解释为段末。普通字段留空保留默认单值，显式填写次数后按数组读取（包括次数为 1 时）。不能引用后面尚未读取的值。
- **可选段／启用条件**：满足条件才读取该字段，否则不消耗它的字节。例如前面已读取 `version`，条件填 `version >= 2`。这是整字段／整段是否存在的判断；同一段内多种互斥布局使用“互斥分支”。
- **偏移起点**：配合“偏移”使用，字节位置从 0 开始。例如偏移为 `4`，选择“当前子段”时从所属子段起点向后 4 字节，选择“整帧”时从整帧起点向后 4 字节。偏移留空时按顺序读取，偏移起点不生效。高级设置中的启用条件和偏移起点均附有说明。

选中被引用的字段后，“被引用位置”列出使用它的长度、数量、条件、校验边界或分支设置，点击跳到对应字段及属性；若属性在高级设置中，自动展开。路径用于区分不同结构体中的同名字段，引用不会因卡片排序而按位置改绑。

### 用 data_length 决定载荷长度

以 `AA 55 | data_length（uint16，小端）| payload | sum8 | 0D 0A` 为例，`data_length` 仅包含 payload 的字节数：

1. 添加 2 字节字段，数据类型选无符号整数，内容约束选普通数据，变量名填 `data_length`，字节序选小端。
2. 添加 payload，数据类型可选原始字节、文本或结构体。回到 `data_length` 的“长度关联”，添加 payload，每单位字节数填 `1`、长度修正填 `0`；payload 自动成为变长字段，在自身属性中只读显示来源及跳转入口。
3. 配置首尾独立固定字节字段。若整帧也通过这个字段确定长度，在整帧属性的“整帧长度表达式”中输入 `data_length + 7`（2 字节固定内容＋2 字节长度＋1 字节校验＋2 字节末尾固定内容）。
4. 样例 `AA 55 03 00 01 02 03 08 0D 0A` 的 payload 为 `01 02 03`，长度为 3，整帧为 10 字节；求和校验范围从整帧起点到校验字段之前。样例已按明确字节验证解码及自动长度／校验编码。

字段位于长度字段之后且在允许的作用域中时才能使用它；如果长度以 2 字节为单位，单位填 `2`。如果长度包含某些额外字节，则按实际规则设置修正量，不能直接照搬上例。

### 枚举标签

整数、布尔和位内容使用“数值／标签名称”表格添加、修改、删除枚举项，例如 `0 → 停止`、`2 → 运行`。数值可输入十进制或 `0x` 十六进制；重复值、超出存储范围或空标签会提示。64 位整数以精确十进制字符串保存；旧布尔标签 `false`／`true` 继续兼容。

标签解释数值的含义，不改变线上存储宽度，也不改变运算使用的原始数值。JSON 标签页仍可完整导入导出协议，无需通过 JSON 编辑枚举。

### 每个字段的数值进制

字段属性提供一个“数值进制”选框，十进制／十六进制统一控制该字段的整数数据值、固定字节、枚举值、分支的等于／区间／掩码匹配、CRC 多项式／初值／输出异或及填充字节。每个子字段独立设置；位字段的枚举和数据值跟随所属字段。

- 无前缀输入按当前进制解释：十六进制下 `10` 是十进制的 16，`FF` 是 255；可用 `0x` 前缀明确指定十六进制。
- 整数显示为十进制或 `0x` 前缀的十六进制；负数如 `-0x2`，不会改成无符号补码。64 位整数保持精确。
- 固定字节及字节数组按字节输入：十六进制 `AA 55` 对应十进制 `170 85`，每个字节范围为 0–255。字节序和原始字节保持不变。
- 字节数、偏移、位号／位宽、数组数量、长度单位和修正量保持十进制；已有表达式原文不自动改写，浮点和文本数据保持原表示。

设置保存为字段的 `displayBase: "dec" | "hex"`，整数默认十进制，原始／固定／保留字节默认十六进制以延续原来的字节输入方式。设置同步影响样例解码、结构化字节流和结构化发送表单；字段之间互不修改设置。样例字段 JSON 使用标准 JSON 数值，精确整数或十六进制可写成字符串，例如 `{"value":"0xFF"}`。

进制切换只改变写法，不重解释已有值；已有编码字节、数值通道、运算、搜索误差及 CSV 原值保持一致。CSV 仍输出精确十进制整数。

## 字段校验

添加字段，选择 uint8、uint16 或 uint32 自动确定 1、2 或 4 字节，再将内容约束设为“校验值”，选择求和、异或、CRC8、CRC16 或 CRC32。所有算法均可配置初始值、输出异或值和“结果按位取反”；CRC 另外配置生成多项式、输入／输出按位反射。数值按校验字段选择的进制显示和输入，范围不得超过其 8／16／32 位宽。

先以初始值开始计算，保留校验位宽内的结果，按需逐位取反，再与输出异或值异或。例如 8 位结果 0x12 取反为 0xED；反射改变位的排列顺序，与取反不同。默认初始值和输出异或为 0，取反关闭；已有协议的显式参数保持不变。计算范围可引用字段开始／结束边界或使用偏移表达式，终点不包含在范围内。校验字段必须占据自己的字节，计算范围不能覆盖自身。

接收时验证，发送时先生成长度再按依赖顺序生成各个校验。可静态确定的自覆盖、循环依赖和重叠在应用前报错；动态布局在实际收发时进一步检查。重复子段中的范围按对应条目解析，不误用其他条目的同名字段。

删除协议前会列出字段映射和发送指令引用。删除草稿模板不会取消已经开始的发送，也不会删除通道或公式；遗留引用必须明确处理后才能应用。

## 子段与条件

### 位段

字段组件库的“位段”按**总字节数**配置，例如 3 字节就是 24 bit；只能设置正整数字节，不与前后字段共用字节。每项可设置名称、最低位、位宽和类型：无符号数值、有符号数值、单比特开关或保留位，也可配置数值含义标签。

位号从最低有效位 0 开始，字节序决定整个位段的存储顺序。新增项目自动寻找尚未配置的位置；“添加保留位”填入下一段空闲位范围。范围越界、重叠或非法总长会阻止应用。保留位不作为数值通道或发送输入，创建新值时默认为 0；重新编码已解码的原始值时保留原有位。超过 64 位的位段和数值也保持精确，超出安全整数范围不会强制转换为浮点通道。

结构画布中的类型、字节数、整帧和段内偏移各自分行显示，卡片及嵌套内容随宽度换行。拖到左右边缘调整同行顺序，拖到上下边缘可在换行处插入。

### 固定字节与条件分支

“固定字节”可以位于任意位置；是否用于帧头或结束断帧另行设置。同步位置必须能静态确定。不要把会在数据中出现的字节串直接用作无转义的结束标志。

“原始字节”保存指定长度或所属段剩余范围内的任意字节，不要求内容等于某个常量；“固定字节”定义必须匹配的常量序列，接收时验证，发送时自动填入。例如 `AA 55 | 任意载荷 | 0D 0A` 的首尾可用固定字节，中间未解码的载荷可用原始字节。普通固定字节不自动触发断帧，需明确指定断帧角色。

“保留字节”用于占位，按长度经过这部分而不赋予业务数值含义，仍保留原始内容。它不代表必须为 0；如果协议要求严格匹配 `00 00`，应使用固定内容。

有界子段只能读取自己的字节范围，不能吞掉后续兄弟字段。剩余字节可保留、要求完全读完，或校验填充字节。子段继承端序，也可覆盖。

“条件分支”按已经读取的字段选择一种布局，支持相等、范围、掩码和受限表达式，并可添加一个默认分支。多个普通分支同时成立是歧义，不能按列表顺序选择。多个独立可选段则分别判断，允许同时存在。

各分支按纵向排列，标题、匹配条件和内部字段分别排布。嵌套子段占用当前可用宽度，内部短字段自动换行；长名称不会覆盖字段卡片。排序只改变展示／编辑顺序，不把“排在前面”作为匹配优先级。

表达式可使用当前和父级上下文；后读字段不能控制前面的长度或分支。64 位整数比较保持精确；不执行用户 JavaScript。无法静态判定的条件会提示，并在收到数据时检查。

## 重复次数与 TLV

所有字段只保留“重复次数”输入框，不再提供重复方式下拉框。直接输入 `-1` 选择重复至段末；输入 `0` 不读取；输入正整数或安全表达式按指定次数读取，例如 `3`、`item_count`、`item_count + 1`。只有直接输入的 `-1` 是专用标记，`(-1)`、`1 - 2` 等负值表达式会报错。默认一次不在卡片上显示重复说明。

配置仍使用 `count` 保存次数或表达式、`until: "end"` 保存按段末重复；不是把 `count` 改为 -1。旧配置打开时按段末重复显示为 `-1`，原有数字、表达式、字段 ID 和引用不自动改写。

整数、浮点、布尔、位段、固定字节、文本、原始字节、保留字节、结构体、互斥分支及 TLV 在满足条件时均可重复至段末。文本和原始字节需确定每项长度；结构体或分支也可按内部字段确定单项终点。每项长度表达式按当前项重新计算，`INDEX` 从 0 开始。无法确定长度、空结构、分支不推进、所属段边界不可靠等情况会提示不能使用 `-1` 的具体原因，输入时拒绝该修改并保留原配置；动态数据导致负次数、零进度或不完整条目时，接收端报告错误，不无限循环。

重复至段末必须有明确的所属段边界，并位于所属顺序段末尾；若后面有 CRC，先把重复部分放入单独的有界结构体。普通字段和结构体的字节数始终表示单项宽度，0 字节按长度表达式或内部字段确定实际长度；固定单项宽度不能代替整个重复区域的结束边界。帧头、帧尾和自动序号必须为单个字段；需要逐项校验或回填时，将这些字段放在重复结构体的内部，不把单个自动字段本身改成数组。

嵌套结构也会检查边界：没有独立长度的外层结构若后面还有字段，不能让内部结构“重复至段末”；旧重复段的整体长度也不能代替每个重复项的边界。此类情况会在校验时提示，不会猜测长度或吞入后续字段。

不再提供独立“重复段”数据类型：选择结构体并配置重复方式即可读取多组子字段，例如三次“编号 uint8＋温度 float32”；不要求每项带类型和长度。旧 `type: repeat` 继续按原语义解析、发送和保存，界面以结构体呈现并标明其字节数限定整个重复区域，字段 ID、引用和旧配置不自动改写。

TLV 保留专用配置，是带 T、L 头部的重复：例如 `01 02 11 22 | 02 01 FF` 表示两项，第一项 T=1、V 长2字节，第二项 T=2、V 长1字节，可按 T 选择不同结构。

TLV 使用可编辑的类型字段 T、长度字段 L 和按类型选择的 V。T、L 的名称、宽度和端序可配置；L 可以描述 V 长度或整个元素长度，并支持长度单位和修正量。发送时反算 L，不能整除或超出存储范围时拒绝发送。

- 每次迭代使用新上下文，必须实际消耗字节。
- 先验证元素终点，再解析 V；即使某分支较短，下一项也从该终点开始。
- 未知类型保留原始 V，可以按原字节重新发送。
- 长度非法、元素越界、头部不完整或分支歧义时，默认停止当前重复段并保留余下字节。
- 可选的“跳过错误项”仅在该项终点已经可靠验证后生效，不扫描或猜测下一个元素的位置。
- 边界或分支错误的帧仍可检查，但不更新数值通道。

以下是一个版本字段后跟 TLV 的简例，所有偏移从 0 开始：

```json
{
  "schemaVersion": 3,
  "id": "tlv-demo",
  "name": "TLV 示例",
  "endian": "little",
  "framing": { "maxLength": 1024 },
  "messages": [{
    "id": "status",
    "byteLength": 11,
    "fields": [
      { "name": "sync", "type": "fixed", "byteLength": 1, "bytes": [170], "framingRole": "sync" },
      { "name": "version", "type": "uint8", "byteLength": 1 },
      {
        "name": "items", "type": "tlv", "byteLength": 0, "lengthFrom": "REMAINING", "until": "end",
        "headerFields": [
          { "name": "tag", "type": "uint8", "byteLength": 1 },
          { "name": "size", "type": "uint8", "byteLength": 1 }
        ],
        "lengthField": "size", "selector": "tag",
        "branches": [
          { "id": "voltage", "equals": 1, "fields": [{ "name": "value", "type": "uint16", "byteLength": 2 }] },
          { "id": "other", "default": true, "fields": [] }
        ]
      }
    ]
  }]
}
```

样例 `AA 01 01 02 00 01 63 03 AA BB CC` 包含数值 256 和类型 99 的三个原始字节。映射数值时使用明确索引，如 `items[0].value`；不存在的元素保持为空，不自动用另一个元素覆盖。

## 范围与兼容

旧 v1/v2 协议和 RoboMaster 模板仍可直接使用。打开编辑器时投影为 v3 整帧结构：旧同步／结束特征转为固定字段，长度与命令位置转为数值字段，校验转为校验字段，消息及子命令转为内联互斥分支。应用前仍使用原采集配置。

迁移保留原字段 ID、消息 ID、嵌套字段路径、数值映射及原消息发送入口；旧文档歧义仍需明确选择布局后发送。新增的公共字段使用新 ID，不按位置替换原有引用。v3 仅保存一份字段规则，不再混用旧版独立 `command`、`headerFields`、`checksums` 或断帧参数。

帧上限 1 MiB，嵌套最多 16 层，每个重复段最多 4096 项，静态字段最多 8192，单次展开字段预算最多 32768。达到边界时报告错误，不无限循环或分配。

本轮不包含字节转义／COBS／SLIP、加密压缩、任意位流、跨帧状态机和依赖后读字段的结构。


## 系统保留名称及长度字段

表达式严格区分大小写，内置变量和函数统一大写。通道管理、协议编辑器的字段属性及整帧属性中，均可展开“保留名称与内置变量”查看清单；枚举标签、分支名称与控件标题不受此限制。

| 名称 | 用途 |
| --- | --- |
| `CH00001`～`CH65535` | 通道引用，兼容 `CH1`、`CH01`；小写 `ch1` 不是编号 |
| `DIFF`、`INT`、`FILTER` | 差分、按采样点积分、常量核／差分系统滤波 |
| `X`、`Y`、`N` | 差分系统输入、输出、当前采样索引 |
| `FRAME_LENGTH`、`PAYLOAD_LENGTH` | 整帧、载荷字节数；由解析边界确定 |
| `LEN(payload)` | 指定字段／数据段的实际编码字节数；两个 float32 为 8 字节，而非 2 个元素 |
| `REMAINING`、`PARENT_REMAINING` | 当前有界段、父段的剩余字节数 |
| `CURRENT`、`PARENT`、`HEADER` | 当前、父级、旧公共头字段作用域 |
| `INDEX` | 数组／重复项索引，从 0 开始 |
| `SEQ` | 自动发送序号；序号字段可自行命名，通过 `valueSource: "SEQ"` 显式关联 |
| `TRUE`、`FALSE` | 布尔常量 |
| `MIN`、`MAX`、`ABS` | 协议表达式的最小值、最大值、绝对值函数 |

这些名称不能用作通道别名或协议变量。内部记录键 `_raw`、`_unknownTail`、`_segmentTails`、`_inferLength`、`rawPayload`，以及安全保护键 `__proto__`、`prototype`、`constructor` 也受保护，维持原来的 JSON 键名。普通小写变量如 `x`、`frameLength` 与系统符号不同，可合法使用。

### LEN：字段的编码字节长度

`LEN(payload)` 只接受字段或数据段路径，返回其实际编码占用的字节数。例如两个 float32 为 8 字节；UTF-8 文本按编码字节而非字符计数；已配置的填充、段内固定内容与校验也计入。可使用 `LEN(group.payload)`、`LEN(CURRENT.payload)` 或 `LEN(PARENT.header)` 指定作用域；函数名严格大写，`LEN` 不能作为字段或通道名称，小写 `len` 仍是普通名称。

普通长度／数量／条件表达式引用已经读取的字段，不能引用自身、后续或未启用的字段。整帧表达式可使用 `LEN(payload) + 9`，前提是 payload 有独立的固定宽度、长度来源或可确定的内部结构。若 payload 又依赖 `FRAME_LENGTH`，或只能依赖尚未确定的段末边界，则会提示无法确定或循环依赖，不会按当前接收块大小猜测。

`LEN` 本身不把字段当作 JavaScript 数组或字符串，也不接受 `LEN()`、数值参数或任意 JavaScript。解析、发送与后台重建共用同一字节长度语义。

旧配置加载时自动迁移并保留字段 ID 和引用：协议保存 `symbolVersion: 3`，全局通道配置继续使用 `symbolVersion: 2`。原有内置 `SEQUENCE` 表达式迁移为 `SEQ`，新协议只提供 `SEQ`；实际字段及成员同名时按作用域识别，不误改数据字段。普通 `seq`／`sequence` 名称不再添加特定协议前缀，已经保存的字段名保持原样。名称搜索仍可不区分大小写，文本搜索仍由对应选项控制。

### 直接在长度字段配置

1. 为 `data_length` 选择 1／2／4 字节无符号整数，内容约束选择“长度关联”。已有其它约束时先确认切换。
2. 在展开的内容约束中填写**本字段的值表达式**，例如 `LEN(payload) + LEN(checksum_0)`。
3. 选择“仅验证”或“解析定界＋验证”。后者只在所选分支不能按自身结构确定长度时求解，结构明确的分支不会被错误的长度值截短或延长。
4. 发送行为可选“自动回填并验证”；使用实际编码字节数计算字段值，然后执行 CRC。字段属性和规则约束修改的是同一条规则，可双向跳转；公式中的字段引用在重命名、移动时同步维护。

长度字段可以位于前置结构体内，例如 `header.data_length`。当表达式为 `LEN(payload) + LEN(checksum_0)` 且校验占 2 字节时，未知 payload 的长度由关系式求出；无需填写单位、修正或重新给 payload 绑定 `data_length`。payload 的“按内部字段确定”使已知命令分支直接读取其结构；变长原始内容可使用“所属有界段剩余字节”，继承这条显式配置的表达式边界。

求解要求长度源先于数据段读取、只有一个未知字节长度，并能以加减乘除唯一解出。已知项可使用受限表达式；未知长度相乘、作除数、参与取整、多个未知段或循环依赖会拒绝。结果必须是范围内的非负整数字节数。未知段后可有固定宽度字段；动态且不能确定长度的后续字段需先提供独立边界。不会猜测长度，也不使用串口接收块大小代替帧边界。

旧 `lengthSource` 配置仍按原规则运行，界面只读展示原关联并允许解除，不自动改写用户协议；旧字段 ID、引用和校验保持。解除容器关联后默认按内部字段确定长度，原始字节字段仍需明确边界。默认模板采用新表达式；已保存的旧模板需显式解除旧关联并配置新表达式，或重新载入默认模板。

### 在数据段查看关联

- 长度字段配置值表达式、定界用途及发送回填；payload 显示备用表达式来源并可跳转。旧绑定只读保留并提供解除入口。
- 旧的数值长度表达式保留原有表示及字段引用；在被引用的无符号数值字段中编辑目标表达式，补全以目标数据段的作用域为准。结构自身的边界、剩余字节和不依赖数值长度字段的表达式仍在该结构中配置。
- 校验算法与起止范围统一在存放校验值字段的“内容约束 → 校验值”中配置。数据段的“关联信息”显示完整覆盖、部分覆盖、条件段内生效及对应字段，并提供“查看校验规则”入口。
- 不需要实际样例即可确定的字段边界和固定偏移会直接判断；动态表达式或无法静态确定的范围标为“范围需结合样例确认”，不把不确定关系当成完整覆盖。互斥分支不相互覆盖，关闭的校验规则不算覆盖。
- 浏览关联、跳转或关闭编辑器不会改变协议；字段 ID、旧标签、长度表示、默认校验设置和撤销行为继续保留。
# 解析结构与规则约束

“整帧结构”决定字节怎样读取、如何同步、按哪个条件分支解释，以及何处结束。“规则约束”是并列标签页，用于长度一致性、CRC／求和／异或和数值表达式断言。

例如用户自定义长度同时包含 payload 和校验字段时，可新增长度验证（官方 2027 V1.0.0 默认模板仅用 LEN(payload)）：

```text
header.data_length == LEN(payload) + LEN(checksum_0)
```

普通附加规则不会改变 payload 的解析边界。需要用于定界时，在长度字段的值表达式中显式选择“解析定界＋验证”，仅为无法独立解析的分支求解边界；验证阶段和规则强弱仍独立设置。

每条规则有独立的参与阶段（解析阶段／完整帧验证／两个阶段）、强度和发送行为。新增附加检查默认弱规则；弱规则失败保留数值供绘图、运算和导出，并显示警告。强规则失败且完整结构已可靠确定时保存错误帧，不输出数值，从帧末尾继续；尚在等待候选帧且解析强规则失败时重新同步。尚未读取的字段不会提前判为通过。

规则表达式从整帧根作用域引用字段，支持大写内置函数、LEN、索引和位段数值；条件分支中的规则可填写启用条件。未启用的规则和条件不满足的规则显示“未执行”；依赖字段缺失会给出原因，并按强弱处理。样例解析逐条显示阶段、强弱、结果及实际／预期值。

选择“自动回填并验证”时，显式选择回填字段及计算表达式；校验规则选择校验值字段、算法和覆盖范围。回填按照值依赖和实际字节覆盖排序，避免多处校验相互影响。重复写入、范围包含自身和循环依赖会被拒绝。普通附加规则不能回填直接参与分支选择或数组数量的字段；显式配置的长度值关系可先根据实际编码段长回填，再用于接收验证。动态覆盖范围在编码样例中进一步校验；不能从任意验证等式反推回填值。

旧协议的长度边界和校验行为保持不变，在“规则约束 → 现有解析规则”查看。旧校验可显式点击“转为独立规则”，保留数值字段 ID 和引用，初始设为两个阶段、强规则、自动回填；随后可自行修改。该转换支持撤销；无法直接转换的局部范围表达式会提示改用明确的字段边界引用，原校验保持不变。字段卡片显示关联用途，字段属性及规则属性均提供跳转入口。

重复段内的校验值和覆盖字段按各自实例匹配，逐项计算并报告具体路径。移动字段时规则的索引引用同步更新；若移动会失去原重复段索引，需先调整规则，不能静默绑定另一实例。回填值可引用位段，依赖按位段所属存储字段排序；新回填改变旧校验范围表达式时，校验按更新后的范围计算。

新增约束保存在协议的 `rules` 数组，配置导入／导出及异步存储会完整保留。基本示例：

```json
{
  "id": "payload-size-check",
  "name": "数据长度验证",
  "type": "length",
  "enabled": true,
  "stage": "validation",
  "strength": "weak",
  "expression": "header.data_length == LEN(payload) + LEN(checksum_0)",
  "send": "fill",
  "targetFieldId": "header-size-id",
  "value": "LEN(payload) + LEN(checksum_0)"
}
```

强验证失败及回填后不满足对应验证会阻止结构化发送；仅验证的弱规则失败允许发送，并在发送预览中显示警告。原始 Hex／文本发送不套用结构化编码规则。
