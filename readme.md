# SerialPlotter

网页端实时数据可视化分析工具，支持串口、TCP 和 UDP 数据流的解析、监视与波形展示。

![License](https://img.shields.io/badge/License-CC%20BY%20NC%20SA%204.0-blue.svg)![JavaScript](https://img.shields.io/badge/JavaScript-vanilla-yellow.svg)![Platform](https://img.shields.io/badge/platform-Web-green.svg)

## 1 项目简介

SerialPlotter 是一个无需后端框架的浏览器端工具，适合调试单片机、传感器、上位机协议和网络数据流。它可以把接收到的数据实时绘制成波形，支持时域、频域、通道配色、统计信息、发送面板和配置导入导出。

界面英文和数字沿用等宽字体，中文使用随项目附带的开源 Noto Sans SC。字体文件和独立授权说明位于 [`assets/fonts/`](assets/fonts/README.md)，离线打开页面也无需在线字体服务。

## 2 主要功能

- 串口通信：基于 Web Serial API，适合现代 Chromium 系浏览器。
- 网络通信：通过本地 `bridge.js` 提供 TCP Client、TCP Server 和 UDP 能力。
- 波形显示：支持时域图和频域图切换，频域模式内置 FFT。
- 频域去直流：可选在 FFT 前移除 DC 分量。
- 多通道显示：右侧通道面板支持名称、颜色、显示开关，以及逐通道放大系数和偏移量。
- 采样缓存最多保留 360 万帧、50 通道；波形监视台的默认可见窗口独立设置，最多 65536 点。缓存按需分配，实际内存随保留数据增长。
- 统计信息：波形监视台显示实际绘图帧率；单通道时还显示最大值、最小值、峰峰值、均值、标准差、主频和周期。
- 交互查看：支持十字光标、双轴拖动条、滚轮缩放、矩形框选放大和手动 Y 轴范围。
- 采集方式：通道数值、Hex 和文本；数值帧支持头部、尾部、8-bit 校验、字节序和多种数据类型，原始字节可按空闲间隔或文本换行断帧。
- 发送面板：支持 Hex/Text、文件发送、定时发送。
- 配置管理：支持本地保存、导入、导出。

## 3 环境要求

### 3.1 浏览器

建议使用 Chrome 或 Edge 等 Chromium 内核浏览器。

- 需要支持 Web Serial API 才能使用串口模式。
- 建议通过本地 HTTP 服务或 HTTPS 方式打开页面，不要只依赖 `file://`。
- Firefox、Safari 目前不适合本项目的串口模式。

### 3.2 Node.js

如果需要使用 TCP/UDP 模式，请安装：

- Node.js 14 或更高版本
- npm 6 或更高版本

## 4 运行方式

### 4.1 网络访问（体验与试用）

适合初次尝试使用，直接访问 https://yssickjgd.github.io/serial_plotter/ 即可。

### 4.2 本地访问（强烈推荐）

如若希望长期离线使用，则可以将仓库下载到本地：

```bash
git clone https://github.com/yssickjgd/serial_plotter
```

然后，在浏览器中打开仓库内的 `index.html` 即可。前端无需构建或安装依赖；TCP/UDP 模式仍需启动本地 Bridge。

### 4.2 启用 TCP/UDP 网络功能

本项目还支持网络数据流的监听、解析、通信、绘图.如若使用该功能，则须克隆该仓库到本地：

```bash
git clone https://github.com/yssickjgd/serial_plotter
```

而后，需要在该仓库内执行下述两条命令，开启服务。注意！使用期间不能关闭该界面：

```bash
npm install
npm start
```

默认会启动本地 WebSocket Bridge，仅监听 `ws://127.0.0.1:8081`。TCP Server 与 UDP 的设备监听端口仍按页面配置工作。

## 5 使用方法

### 5.1 串口模式

1. 打开左侧“通讯”选项卡。
2. 选择“原生串口 (Web Serial)”模式。
3. 设置波特率、数据位、停止位和校验位。
4. 点击“连接”，在浏览器弹窗中选择串口设备。
5. 接收数据后可在下方“字节流监视台”和上方“波形监视台”看到内容。

### 5.2 TCP Client 模式

1. 启动 `node bridge.js`。
2. 在“通讯”里选择 “TCP Client (Bridge)”。
3. 填写远端 TCP Server 的 Host 和 Port。
4. 点击“连接”。

### 5.3 TCP Server 模式

1. 启动 `node bridge.js`。
2. 选择 “TCP Server (Bridge)”。
3. 填写要监听的本地端口。
4. Host 字段可以忽略，桥会在 `0.0.0.0` 上监听该端口。
5. 让外部 TCP 客户端连接这个端口即可。

### 5.4 UDP 模式

1. 启动 `node bridge.js`。
2. 选择 “UDP (Bridge)”。
3. 填写远端 Host 和 Port，这表示发送目标。
4. 填写本地监听端口，用于接收 UDP 数据。
5. 如果本地端口留空，程序会优先使用 Port 作为默认监听端口。

## 6 界面说明

### 6.1 波形监视台

- 时域图：显示通道采样值；横轴可选采样点或秒（s）。
- 频域图：可选择无窗、Hann、Hamming、Blackman 或 Flat-top 窗，默认 Hann。FFT 前可选去直流，频谱按窗的相干增益校正为单边线性幅值。横轴可选 FFT 频点编号或 Hz，并可选线性或对数间距；纵轴可选线性幅值或对数间距的幅值（不是 dB）。对数横轴从第 1 个频点开始。对数纵轴自定义下限为 0 时，零附近采用线性刻度，线性区间上限为当前可见频谱峰值与自定义上限中较小者的 1%，以上连续过渡到对数间距；全零频谱采用线性刻度。刻度和光标始终显示原幅值，缩放期间固定过渡位置，右键重置后重新自适应。正数下限和自动范围继续采用标准对数刻度，零幅值绘在显示下界。
- 实时采集时，FFT 使用波形监视台窗口内的最新样本；暂停捕捉后，FFT 使用时域图当前 X 轴可见范围内的样本。暂停期间可切到时域图滚动或缩放，再切回频域图查看对应频谱；恢复捕捉后重新使用最新窗口。单通道频域统计也采用相同的数据范围。
- “最大采样点数”控制历史保留量，“波形监视台内采样点数”控制默认时域窗口与实时 FFT 输入，后者不能超过前者或 65536。减小保留量时窗口会自动缩小；时域图右键恢复最新窗口。
- 中央从上到下为波形监视台、字节流监视台及底部工具面板。底部无额外标题，依次为缓冲区设置、时间定位、搜索三行；输入框统一配色和尺寸，窄窗口按功能组换行，面板不随波形与字节流之间的分隔条改变高度。时间定位与搜索仅暂停捕捉时可操作，仍会同步跳转波形监视台。系统时间和相对时间使用下拉框选择，系统时间精确到 1 ms，相对时间以 s 为单位；暂停时系统时间默认填入最新保留帧的时间，无数据帧时填入当前时间。相对时间从当前保留的最早采样帧开始计算；旧帧被淘汰后零点随之移动。定位会把最近的帧同步移到两个监视台中央，在字节流中高亮该行，并在时域图中绘制蓝色竖线。波形仅在已应用的通道数值模式下显示；Hex/文本模式自动隐藏波形。
- 两个监视台使用一致的标题和统计栏，底部独立定位与搜索面板不随波形和字节流之间的分隔条调整高度。窗口变窄时统计项完整换行，定位和搜索控件成组换行；没有单通道统计时波形统计行自动收起。
- 所有互斥选项使用下拉框；鼠标悬浮时滚轮向下选择下一项、向上选择上一项，边界处停止并跳过禁用项，Ctrl＋滚轮仍用于浏览器缩放。独立开关保留复选框。切换时域/频域后只显示对应设置，选择自定义 Y 轴范围后才显示边界输入框。
- 时域和频域分别保存自动/自定义 Y 轴策略及最小、最大值，切换模式时输入框恢复该模式的设置。自定义范围要求有限数值且最大值大于最小值；频域对数轴允许最小值为 0，最大值必须为正数。无效范围会显示原因并暂用自动范围；重新应用 Y 轴设置会清除当前模式的临时框选缩放。旧配置的共用策略仍可读取，新配置使用 `plotYScaleModeTime`、`plotYScaleModeFreq` 分别保存策略。
- 左侧提供同级的“通讯”“帧格式”选项卡：通讯包含连接参数和配置文件；帧格式包含数据格式、原始数据断帧、帧首、帧尾、校验位和数值解码，按采集方式显示相应设置。右侧提供“字节流”“波形”“导出配置”选项卡；字节流配置在所有模式下可用，波形配置仅通道数值模式可见，其中显示方式和通道列表同时上下展示。侧栏宽度可拖动调整。底部首行为缓冲区设置；通道变换按 `y = kx + b`，参与绘图、FFT、光标、统计和 CSV，原始字节不变。
- Hz 和 s 按最近测得的接收帧率换算；帧率尚未测得时显示 `-- Hz` 或 `-- s`。采样间隔稳定时，换算结果才较准确。
- 鼠标悬浮时，两种模式使用一致的提示框：时域显示时间（s）与采样点索引，频域显示频率（Hz）与 FFT Bin，始终同时显示两种横轴信息，不受横轴单位选项影响。采样点索引与时域横轴一致，从当前保留的第 0 点开始；通道交点数值仍单独显示。
- 单通道时会显示统计信息。
- 单通道统计的主频单位跟随频域横轴（Hz/Bin），主周期单位跟随时域横轴（s/Sample），在两种绘图模式下均有效。Hz 和 s 使用最近测得的采样率换算，未知时显示 `--`；Bin 和 Sample 无需采样率即可显示。
- 波形监视台的“绘图帧率”在时域统计完成的画布重绘，在频域统计实际更新并呈现的新频谱，重复绘制缓存频谱不计入；字节流监视台的“帧率”统计接收帧数。暂停后无新绘制时前者为 `0 FPS`。
- 持续接收时，频谱最短每 100 ms 更新一次；仅有新采样而频谱尚未到期时不重复绘制缓存频谱。鼠标操作和显示设置变化仍可触发即时重绘。实际帧率取决于通道数、采样点数和设备性能。
- 统计栏优先使用通道自定义名称，未修改名称时显示默认的 CH01、CH02。
- 在绘图区按住鼠标左键拖出矩形，松开后放大框内的横轴与纵轴范围；拖动过小不会触发缩放。时域和频域均可使用。
- 鼠标位于绘图区或下方 X 轴刻度带时，滚轮缩放横轴；位于右侧 Y 轴刻度带时，滚轮缩放纵轴。横轴放大后可拖动底部滚动条，纵轴放大后可拖动右侧滚动条。
- 实时采集时，横轴滚动条离开最右侧后固定当前样本窗口；新帧不会改变所选波形，直到该窗口的最早样本被缓冲区淘汰，才从左侧随旧帧淘汰而更新。拖回最右侧或右键恢复最新数据跟随。
- 在绘图区点击右键恢复完整横轴范围，并撤销框选或滚轮带来的纵轴缩放。原有的手动 Y 轴范围会恢复。

### 6.2 字节流监视台

日志颜色统一如下：

- 蓝色：接收成功 `RX`
- 黄色：接收错误 `RX[原因]`
- 绿色：发送成功 `TX`
- 红色：发送错误 `TX[原因]`

说明：

- 未通过验证的数据会显示时间戳。
- 错误原因会直接附在 `RX` 或 `TX` 后面。
- 较长的 Hex 记录会随监视台宽度自动换行，续行与第一行 Hex 字节的起始列对齐（普通记录为 `RX ` 或 `TX ` 后）。
- 在底部自动跟随最新记录；向上滚动后固定所查看的记录，滚回底部恢复跟随。记录超出保留窗口后会显示当前最早的记录。
- 接收显示及搜索类型由帧格式页已应用的采集方式决定。通道数值显示原始解码值，Hex 显示原始字节；文本按字符集解码，非法编码和不可打印控制字符显示白色 `�`。CR/LF/TAB 保留可见转义且不计失败，统计栏显示失败数、总字符数和比例。发送格式和间隔单位使用 Hex/Text、s/Hz 下拉框；旧配置的 ms 换算为 s。
- 通道数值按字节流显示区的当前宽度自动分列，个位通道编号显示为 `CH01`～`CH09`。采用科学计数法，正数预留负号位置，同列数值按 `e` 对齐，有效数字位数可在显示方式中配置。数值位数变化不挤动后面的通道，调整窗口或侧栏宽度后自动重新排版；窄窗口内自动换行，原始采样和搜索精度不受显示精度影响。
- 文本字符统计直接计数，不创建显示或搜索用的位置对象；UTF-8、ASCII 和 UTF-16 的非法字节直接判定，减少异常处理开销。历史文本复用行高信息，只为可见记录生成换行和高亮内容；新字节补全跨帧字符、记录被覆盖或宽度改变时更新相应布局。原始字节、白色替代字符及失败统计规则保持一致。
- 暂停捕捉后可按接收显示格式搜索十六进制字节、解码文本（都可跨帧匹配，文本支持中文和多字节字符）或指定误差范围内的解码通道数值。文本搜索可勾选“区分大小写”，默认勾选；修改该选项后清除旧结果，下次操作重新搜索。数值搜索默认检查全部通道，也可展开通道复选列表，仅搜索选中的多个通道。通道选项同时显示编号与自定义名称（如 `CH01 · acc_x`），修改名称后同步更新；长名称可悬浮查看完整文字。通道编号及默认名称统一为 `CH01`～`CH09`、`CH10`～`CH50`，旧配置中的默认名称自动兼容，自定义名称保留。
- 搜索按钮依次为“就近搜索”“上一个”“下一个”；“就近依据”可下拉选择波形或字节流，默认字节流；Hex/文本模式固定使用字节流位置。处于最新跟随状态时以最新帧为起点，查看历史时使用窗口中心；频域模式使用保留的时域窗口，字节流按实际换行后的记录显示区确定中心，不以点选行作为起点。返回最新跟随状态后恢复以最新帧为起点。
- 没有选中的搜索结果时，先确定就近结果：首次“上一个”选择其后一个结果，首次“下一个”选择其前一个结果。已有高亮结果后，“上一个”选择较早的结果，“下一个”选择较新的结果，均首尾循环。移动窗口、时间跳转或切换就近依据不会清除当前结果，点击“就近搜索”才按新位置重新定位；修改搜索条件则清除旧结果，下次点击按钮重新搜索。相同条件复用搜索结果，异步搜索使用点击按钮时的位置。
- 搜索会同步定位两个监视台。所有当前可见的匹配在字节流中高亮，并在时域图中以黄色竖线标出，当前结果使用橙色。底部控件常驻时，字节记录区至少保留四行；拖动上下分隔条时，增加的空间用于字节记录区。发送框高度固定为四行，更多文本在框内滚动。
- 接收速率按真实接收到的数据块统计，不会因为错误帧重复放大。
- 帧尾不匹配时，错误记录显示重同步过程中实际丢弃的字节，不重复列出相互重叠的候选帧；尚不足一帧的末尾字节会继续等待输入，暂停或断开时以“帧未完整”记录一次。
- 大于 5 万帧的 CSV 使用 Chrome 或 Edge 的文件保存接口分批写入，避免在内存中拼接完整 CSV。建议暂停采集后导出，以免导出过程中最早记录被覆盖。

右侧“字节流”选项卡中可配置：

设置分为同级的“字节流显示方式”“字节流显示配置”“颜色配置”三个小节；颜色集中在独立小节，使用与通道列表相同的小色块和紧凑行距。

- **显示方式：**Hex 每行字节数自动适应宽度，或选择 8、16、32 字节；可按 2、4、8 字节分组、显示帧内或接收字节流偏移，并附加 ASCII 对照。文本可选择白色替代字符或非法字节转义、可见换行转义或实际换行，以及 Tab 转义或 4、8 个空格。
- **通道数值：**字节流记录统一采用科学计数法，按 `e` 位置对齐，正数预留负号空位。有效数字位数包含整数位，可设为 1～17 位，默认 6 位，例如 `CH01= 1.23456e+2`、`CH02=-1.23456e-3`。修改后已有记录立即更新，设置保存在本地及 JSON 配置中；只改变显示精度，不改变原始样本、数值搜索、波形、统计或 CSV 导出。非有限值显示为 `NaN`、`Infinity`、`-Infinity`。
- **时间与刷新：**时间戳可显示时分秒和毫秒、完整日期时间、相对时间或隐藏；相对时间从当前保留的最早 RX 帧起算。RX/TX 标记可隐藏。字节流有变化时在下一次浏览器绘制前更新，不设置固定刷新率上限，同批到达的数据合并显示，原始记录完整保留。旧配置中的刷新率字段自动忽略；滚动查看历史时保持已选位置，无新数据时不持续刷新。
- **关键词与颜色：**关键词逐行输入，可选择 Hex 或文本。Hex 按原始字节匹配，文本按所选字符集解码后匹配并支持大小写开关；数值模式下文本关键词匹配 `CHx=数值`，Hex 匹配到原始帧时高亮该记录。可分别设置关键词、RX、TX、RX 错误、TX 错误的文字颜色，以及当前搜索命中和其他搜索命中的背景颜色；波形搜索竖线同步采用对应颜色。搜索高亮优先于关键词，无效字符始终显示白色。
- **筛选与折叠：**分别筛选 RX、TX 和错误记录。长帧可折叠为指定行数，展开／收起按钮位于首行右侧，不额外占行；正文预留按钮位置，窄窗口中也可操作。
- 显示设置立即生效并保存在本地及 JSON 配置中。旧配置沿用原有显示效果；调整这些设置不会重建或清空历史，不改变原始字节、字符失败统计或导出内容。搜索仍覆盖完整保留记录；定位到被筛选或折叠的 RX 帧时临时显示并展开该帧。

### 6.3 采集格式与应用

- 左侧“帧格式”的采集方式依次为 Hex、文本、通道数值、自定义帧（暂未开放）。下拉框和开关自动应用，文本或数字输入完成后失焦或按 Enter 应用。无效输入保留当前格式和数据；未完成输入不覆盖已保存配置。帧首、帧尾和校验未启用时隐藏相应设置。
- 通道数值模式保留数值解码、帧首、帧尾和校验配置，并显示波形。Hex/文本模式隐藏这些配置及波形，保留暂停、清空和容量设置，此时容量标签为“最大帧数量”，按自动断出的帧数控制；切回数值时恢复隐藏配置。
- Hex 仅按空闲间隔断帧，默认 `0.001 s`。文本可选空闲、`\r`、`\n`、`\r\n` 或 `\n\r`，默认空闲。空闲按浏览器收到数据块的到达间隔判断，计时器延迟时也先检查期限；它不能恢复设备在同一浏览器数据块内的发送间隔。
- 换行符保留在前一帧中，空行也保留，支持跨块分隔符及 UTF-16 完整字符断帧。每条记录取其首个数据块的系统时间。暂停或断开会保存尾部字节；换行模式下未结束记录标注“帧未完整”，仍可定位及搜索。
- 文本字符集支持 UTF-8、严格 ASCII、GBK（兼容 GB2312）、GB18030、Big5、UTF-16LE、UTF-16BE、Shift-JIS、Windows-1252，默认 UTF-8。显示及搜索使用同一解码和原始字节映射，中文换行与搜索高亮保留源字节位置。
- 数据格式下提供“重建历史数据”复选框，默认勾选并保存到配置。勾选时，改变采集方式、解析规则、字符集或断帧方式会保留原始字节和到达时间，分批重新断帧、解码并显示进度；取消勾选后，变更规则会清理 RX/TX 缓冲区，使用新格式继续采集，不弹窗。仅勾选或取消本身不会清理数据，无效设置也不会清理。
- 大于等于 512 KiB 的历史会按需使用后台线程：并行解码数值、统计文本及准备长记录显示，最多使用浏览器报告的逻辑处理器数减二个线程；不足三个或不支持后台线程时自动异步回退。断帧仍保持字节顺序，字符分块遵循编码边界，原始字节不会被转移或改写。
- 重建先完成固定历史快照并切换视图，再分批处理重建期间的新数据；持续采集无需暂停即可恢复新格式下的实时更新。旧搜索结果失效，定位、搜索和导出在重建及接收队列处理期间暂时禁用。暂停和断开的收尾边界也会重放，避免拼接不同采集段。显示窗口仍受容量限制，勾选重建时格式切换本身不裁剪原始历史。
- 文本统计按 Unicode 字符而非字节计数；重建时从保留原始历史重新统计，随后继续累计，清空归零。为支持修正错误帧格式后恢复数据，尚不能解析成有效数值帧的原始字节也保留，因此持续不匹配的数据流会额外占用内存。
- 长文本分批准备并显示进度，监视台只渲染可见行；原始字节、全部记录及搜索映射仍完整保留。
- 配置新增 `captureMode`、`textEncoding`、`textBoundary`、`idleGapSeconds`。旧配置缺少这些字段时恢复通道数值、UTF-8、空闲、`0.001 s`（已有配置中明确保存的间隔保持不变）。


### 6.4 数据导出

- 右侧“导出配置”独立于通讯页的 JSON 配置导入/导出。通道数值导出 CSV，可勾选“带时间戳”加入 `Timestamp` 列，采用含毫秒的 ISO 8601 UTC 时间（末尾 Z）。Hex 支持原始字节文件（.bin，无元数据）和空格分隔的 Hex 文本（.txt）；文本模式导出 UTF-8 文本。
- Hex/文本可选择 RX、TX 或 RX＋TX，合并时按记录顺序导出。可读文本可选时间戳及 RX/TX 标记，原始字节文件始终保持字节不变。
- RX 与成功发送的 TX 各自保留最多“最大帧数量”条显示记录，TX 导出不受监视台日志条数限制。修改解析规则保留 TX，清空缓冲时一并删除；降低容量淘汰最早显示记录。
- 大于 5 万帧或原始字节超过 32 MiB 时使用 Chrome/Edge 文件保存接口分批写入；导出过程中记录被覆盖会停止并提示，建议暂停后导出。

## 8 帧格式说明

基本结构如下：

```text
[可选头部] + [数据负载] + [可选尾部] + [可选校验]
```

示例：

```text
[AB] + [payload] + [0D 0A]
```

如果启用了校验位，校验值位于帧尾之后。

## 9 常见问题

### 9.1 串口无法连接

- 确认浏览器是否支持 Web Serial API。
- 确认页面是否通过本地 HTTP 服务或 HTTPS 打开。
- 检查串口是否已被其它程序占用。

### 9.2 TCP/UDP 无法监听

- 确认已经运行 `npm start`。
- TCP Server 模式下，请填写要监听的本地端口。
- UDP 模式下，请填写本地监听端口；远端 Host/Port 只是发送目标。
- 如果是 TCP Server，请确认该端口未被其它程序占用。
- 注意！目前暂不支持打开两个网页分别作为 Client 和 Server 这种特殊的工作模式。

### 9.3 波形不显示

- 在右侧“通道显示配置”中勾选需要显示的通道。
- 检查 Y 轴范围是否合适。
- 切换到自动 Y 轴缩放试试。

### 9.4 发送定时任务异常

- 如果连接断开，程序会自动停止定时发送。
- 出错信息会出现在字节流监视台，不会再弹出浏览器提示框。
